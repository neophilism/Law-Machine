# LM-044 follow-up: quarantine-to-private-editorial-review (CONTRIBUTING)

This follow-up integrates the preflight quarantine candidate from LM-044 PR #42 with the existing bounded provider-free source parsers. `preparePrivateSourceReview()` first snapshots the input bytes, validates tenant/document IDs, digest, size, kind and private quarantine key, then invokes exactly one appropriate parser for UTF-8 text, Markdown, DOCX, legislative XML or PDF. It validates exact source digest parity before returning an editorial reading view.

**This is not a secure public upload or publish path.** No storage adapter, live network call, HTTP route, database credentials or public source exposure is created. The caller must independently authenticate the editor and enforce tenant ownership before passing source bytes to the function, and the returned preview must remain private. It does not return original bytes, and reduces parser failures to a content-free error code to avoid leaking private excerpts, stack traces or paths. Source provenance remains unverified, and `readyForRuleCompiler`, `readyForPublication` and `substantiveLegalAuthorityVerified` are always false. Unverified PDF page extraction needs further manual correction.

The synthetic tests cover harmless text/Markdown processing, preservation of reading view versus exact byte source digest, rejection of manipulated digest and invalid source kind, non-disclosure of detailed parser errors and fixed unverified/publication flags. These are code-level fixtures, **not** live authenticated storage/end-to-end scans. The owner-approved LM-044 milestone still requires fully accepted LM-043 identity integration, private object storage, authenticated upload/download, actual isolated antivirus/parser processing, durable job recovery, retry/failure semantics, and tenant isolation E2E. The branch depends on PR #42 and must only merge on a clean tested current main. No real private documents or official law claims. Roll back with a tested revert; no migration.
