# LM-015: typed amendments and derived consolidation

The module maintains separate artifacts for the pinned baseline, amendatory instruction set, and the platform-generated projected consolidation. Operations insert, replace, repeal, and renumber exactly addressed baseline-version provisions. All instructions require version, source-byte digest, target ID and source ID; missing and ambiguous targets fail closed. An invented legal text can never act as a source of truth.

Multiple edits to the same target require explicit 'after' dependencies defining a total order. Cycles, unknown predecessors, duplicate IDs and conflicting edits stop projection. A repealed target cannot be edited without an explicit rule outside this bounded subset. On any failure, the output is 'unresolved' with a completely unchanged baseline projection and issue diagnostics, not an arbitrarily partially applied generated law. When successful, the result is labeled Generated consolidation — not an official source, with each reconstructed provision listing its amending instruction IDs; the input baseline remains unchanged.

Tests validate insert/replace/repeal/renumber, immutable baseline, no guessed conflict resolution, same-target precedence, cyclic declarations, source identity mismatch, nonexistent provisions, and a repair attempt after repeal.

No database, provider integration, executable uploaded content, real government filing or external security certification. Rollback: checked revert of this unit. LM-014 temporal applicability and source packs will gate use of any projection as current law; this module alone does not claim enactment. Current-head foundation and workspace CI are required before merging.
