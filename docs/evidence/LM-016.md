# LM-016 version diff, correspondence and dependency invalidation

LM-016 adds a provider-free, deterministic comparison between two immutable `NormalizedDocument` versions. A provision correspondence must be supplied explicitly and is labeled provisional or editor-confirmed. Matching labels and version-local IDs do not automatically establish legal identity or unchanged meaning. Each paired change reports text, displayed citation, hierarchy, source span and full-source digest differences; all `meaningStatus` values remain `unreviewed`. Absent correspondence produces separate added/removed entries.

Downstream rule, scenario, scene, translation and citation artifacts retain exact prior version and source digest references. The dependency graph marks source-linked artifacts stale when a matched provision changes or disappears, then propagates invalidation to dependent artifacts with a bounded indexed queue. Missing/ambiguous correspondence, forged source digests, duplicates, dangling downstream IDs and malformed collections stop comparison rather than guessing.

The old source is never modified. A retained `VersionedSourceStore` fixture demonstrates that a previous release's exact quote still resolves against its pinned historical version after a newer version is compared and stored. When the overall source digest changes, corresponding anchors are conservatively invalidated; the engine does not silently reanchor a citation to a newer source.

Tests: `tests/unit/version-diff.test.ts` covers an edited operative exception invalidating a rule and its scenario/scene/translation, citation-only renumbering with unresolved meaning, absent correspondence, rejected invalid mappings, source forgeries and reproducible historical citations.

Security and rollback: pure, bounded TypeScript; no external requests, private documents, database, stored migrations, rendering, code execution or provider keys. Changes are confined to the legislation package, fixture tests and canonical PR registry. Revert the checked PR and prevent downstream releases from trusting derived invalidation output until revalidated. AI-led review is not an independent audit.

Acceptance requires final-head GitHub Actions `foundation` and `workspace` including `pnpm check`, audit, production build and actual browser tests.
