# LM-046 — deterministic lease/fencing oracle (CONTRIBUTING)

A provider-free \`FixtureLeaseQueue\` defines concrete retry, claim, heartbeat, checkpoint, cancellation, completion, dead-letter and idempotency transitions under bounded inputs. Every leased attempt has a monotonic fencing token. Expired worker claims cannot update a recovered job. Cancellation revokes the old fence. Requeued failures use bounded exponential delays. Checkpoints are detached canonical JSON, source exception strings cannot become arbitrary job error codes, and organization-scoped duplicate jobs must carry identical intent. Synthetic tests cover replay, stale workers, retry deadlines, cross-tenant lookup and mutation isolation.

**NOT durable processing or LM-046 acceptance.** This is deliberately in-memory, synchronous and single-process. Its behavior is an executable oracle for the future PostgreSQL implementation, not crash/restart persistence. No public route, long-running HTTP request, remote provider, worker process, job table migration or production job runner was enabled. To accept LM-046 later, implement atomic PostgreSQL claims/leases with fencing, real process-kill and restart tests, idempotent compilation/import sinks, durable checkpoints, cancellation and dead-letter recovery, and independent job entry point. LM-044 secure storage and LM-043 identity completion are also prerequisites for production jobs. Revert this module and tests to roll back; there are no migrations or credentials.
