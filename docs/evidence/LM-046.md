# LM-046 — deterministic lease/fencing oracle (CONTRIBUTING)

A provider-free \`FixtureLeaseQueue\` defines concrete retry, claim, heartbeat, checkpoint, cancellation, completion, dead-letter and idempotency transitions under bounded inputs. Every leased attempt has a monotonic fencing token. Expired worker claims cannot update a recovered job. Cancellation revokes the old fence. Requeued failures use bounded exponential delays. Checkpoints are detached canonical JSON, source exception strings cannot become arbitrary job error codes, and organization-scoped duplicate jobs must carry identical intent. Synthetic tests cover replay, stale workers, retry deadlines, cross-tenant lookup and mutation isolation.

**NOT durable processing or LM-046 acceptance.** This is deliberately in-memory, synchronous and single-process. Its behavior is an executable oracle for the future PostgreSQL implementation, not crash/restart persistence. No public route, long-running HTTP request, remote provider, worker process, job table migration or production job runner was enabled. To accept LM-046 later, implement atomic PostgreSQL claims/leases with fencing, real process-kill and restart tests, idempotent compilation/import sinks, durable checkpoints, cancellation and dead-letter recovery, and independent job entry point. LM-044 secure storage and LM-043 identity completion are also prerequisites for production jobs. Revert this module and tests to roll back; there are no migrations or credentials.

## PostgreSQL durable lease transitions (contributing implementation, not complete LM-046)

Migration 0004 adds bounded attempts, monotonic fencing, queue availability, worker leases, JSON checkpoints and result/error fields. SECURITY INVOKER SQL functions enforce organization-local session scope, idempotent enqueue with intent collision denial, row-locking \`FOR UPDATE SKIP LOCKED\` claims, compare-and-swap lease/worker/fence guards on heartbeat/checkpoint/complete/fail, cancellation and expired dead-letter reaping. Server timestamps are authoritative; fixture clients cannot claim a job in the future by passing a forged clock. PostgreSQL CI exercises duplicate claims, session stale worker recovery, revoked fencing, idempotency conflict, dead letter and cross-organization attempts.

**Security limitations and acceptance gaps:** No separate restricted worker database role is provisioned; SQL session GUCs are NOT authenticators when arbitrary client SQL is possible. Caller must use a server-only least-privileged worker role with verified organization assignment and must not expose SQL functions directly to browsers or untrusted tenants. No worker daemon, checkpointed content store, host restart/crash harness, object-store publication, backup, exactly-once side-effect sink, or production migration has been exercised. The test-only migration inverse is destructive; use PITR or forward fix in production. This is partial LM-046 development pending LM-043/LM-044 and actual crash recovery acceptance.


## PostgreSQL worker adapter contribution (not production LM-046 acceptance)

A provider-neutral server-side \`PostgresLeaseWorker\` now executes each LM-046 SQL lease, heartbeat, checkpoint, completion and failure under separate transaction-local scoped \`app.organization_id\` / \`app.worker_id\` settings. It never leaves transaction scopes on pooled connections after failure; failures roll back and release. The handler runs outside the claim transaction, while fenced SQL CAS operations prevent stale workers from committing later. Invalid output digests and provider handler failures are recorded only as allowlisted error codes, not private exception strings. Unit tests check valid processing, idle, lost lease, retry, strict input validation, transaction rollback, scope setup, and connection cleanup.

The adapter deliberately has no provider client, worker daemon, long-running job loop, HTTP route or production database credentials. A live worker must supply an independently provisioned dedicated least-privileged role, verified organization context and idempotent external side-effect sink, and must undergo real crash/restart and backup/restore tests. No source bytes or tokens are transmitted or logged. Revert only this adapter and tests for rollback.
