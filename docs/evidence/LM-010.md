# LM-010: official legislative XML and metadata adapter evidence

USLM and the House Bill DTD are deliberately separate families. The USLM detector requires its declared GPO namespace; the House-format detector requires the distinct no-namespace bill/legis-body structure. Unsupported formats fail closed instead of being silently interpreted as the other schema.

The dependency-free bounded scanner preserves source bytes and SHA-256 alongside a separate structural reading view. It maps provision tree identity, explicit ancestor relationships, displayed labels, headings, text and XML source offsets. It bounds bytes, tokens, nesting and IDs. Only a narrowly allowlisted House bill DTD external identifier is recognized as metadata; no XML DTD, system identifier, filesystem path, network URL, XInclude or entity is ever fetched or expanded. Internal subsets, unsupported entities, active content and malformed nesting are rejected.

Congress.gov and GovInfo adapters use fixed HTTPS hosts and allowlisted resource identifiers, accept explicit fixture snapshots without any API key or network access, and require credentials and a server-only runtime for live lookups. Live requests use a bounded timeout, redirects disabled, byte-limited JSON reading and no-store caching. API keys are not included in returned public provenance URLs, logs or diagnostics. Returned metadata are immutable-content snapshots pinned with SHA-256 of canonical JSON; they are upstream metadata, not assertions that a bill is enacted.

Tests exercise both supported families with separately authored fictional bill XML examples resembling the published GPO layouts, exact original-byte/digest separation, nested sections, duplicate identity detection, DTD and entity attacks, wrong families, malformed inputs, fixture-only cache, live response bounds and credential handling. No actual congressional document text is presented as current law or executed as a rule.

Public specification references: GPO USLM schema (usgpo/uslm), GPO House Bill DTD (usgpo/bill-dtd), api.congress.gov and api.govinfo.gov. These adapters implement a safe supported subset, not full XSD/DTD conformance; real official files need additional conformance fixtures as other source-pack work proceeds. No provider credentials, data migrations, deployments or paid services. Roll back by a checked revert of this work unit. Required exact-head gates: foundation, workspace, pnpm check/audit/build and browser test. AI-assisted code review is not an independent audit.
