# LM-006 headless SDK — security and test evidence

Implements a provider-independent public package boundary, exact schema and engine negotiation, source-verified immutable release sessions, scoped provision lookup, ambiguous citation diagnostics, explicit unsupported simulation, and structured error vocabulary. The SDK cannot silently load another version when a pinned source is absent.

Source/security review: \`canonicalJSON\` creates a detached JSON snapshot before it is recursively frozen and exposed. Subsequent mutation of the caller's original data cannot rewrite citations. The SDK requires the caller's separately trusted manifest digest, matching release ID, source bytes and all verified asset bytes. There are no private storage adapters, dynamic rule execution, network requests or credentials. A future publisher trust root remains separate from self-calculated hashes.

Automated coverage: unit tests cover successful CLI-compatible fixture loading, incompatible engine/schema, wrong or tampered releases, not-found and ambiguous lookup, immutable snapshots, and simulation's explicit unsupported result. The new \`pnpm smoke:sdk\` runs a real headless command-line fixture as part of \`pnpm check\`. Further acceptance requires exact-head foundation/workspace CI, dependency audit, production build and browser checks.

No schema migration or deployment. Rollback via reviewed revert of this SDK module, smoke script and package.json check extension. No independent human audit or legal interpretation assessment is claimed.
