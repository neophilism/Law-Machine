# LM-022 versioned civil calendars and hypothetical deadline calculations

LM-022 provides a provider-free bounded calendar engine with explicit `calendarId` and version, IANA time zone, configured weekend weekdays, **explicit observed holidays**, counting convention, after-hours cutoff, month-end choice and nonbusiness-day extension. No universal jurisdictional holiday, deadline trigger, effective law or governing counting rule is assumed by default.

Duration units are **calendar days, business days, calendar months and elapsed real hours**. Calendar months are computed by calendar dates and explicit end-of-month clamping, not approximated as 30-day intervals or 180 days for six months. Elapsed-hour calculations use an actual UTC instant and report both UTC instant and the destination IANA-zone civil time, allowing daylight-saving changes without fabricating wall-clock-hour conventions. For date-only triggers, a missing time needed for cutoff resolution generates `TRIGGER_TIME_UNKNOWN`. Ambiguous month-end, business-day extensions, start counting and cutoff behavior yield explicit interpretation-required outcomes rather than a guessed deadline.

All legal counting policies require version-pinned `sourceRefs`; no source means a visibly unresolved result. These references **identify claimed provenance only** and do not independently authenticate official law/source bytes. The engine's date is for *fictional tests and explicitly marked hypothetical modeling only*; it is not an authoritative statutory deadline or filing tool for an actual person's case.

Acceptance fixtures in `tests/unit/calendar.test.ts` independently cover: leap-day February (2024 vs 2025), January month-end, six calendar months versus 180 days, weekend/declared holiday crossing, Friday cutoff with Monday holiday, missing legal policy/source, missing trigger local time, nonbusiness extension uncertainty, spring-forward and fall-back daylight-saving elapsed-hour behavior, malformed dates, invalid time zones and bounded quantity validation.

Security: no database, React, network APIs, clock-guessing, uploading, executing source code or credentials. Avoid trusting unreviewed `sourceRefs` until verified release/baseline material is supplied. No migrations; rollback via checked revert while preserving previous package exports for other milestones. The source/security review is AI-led and does not claim independent certification.

Require current-head `foundation` and `workspace` GitHub Actions with `pnpm check`, audit, production build, and browser tests before merge.
