# LM-026 replay streams — validation and rollback

Provider-free deterministic xorshift32 random streams, namespaced by a derived canonical run identity and stream name. The run identity hashes engine version, calendar version, model digest, scenario ID, seed and canonicalized facts. Simulation random streams are **not cryptographic** and must not be used for secrets, access decisions or token generation.

The source-bound unit tests cover deterministic stream output, isolation of named streams when one subsystem consumes additional events, version-dependent identity, bounded import/export, checkpoints, fixed decimal rounding and incompatible/malformed inputs.

The browser/Node parity test transpiles the actual canonical integrity and replay source to browser-executable JavaScript and exercises identity hashing, named-stream values, xorshift32 values, fixed rounding and replay checkpoints on the same synthetic inputs. A separately calculated six-number golden xorshift32 vector catches a shared implementation regression. This is a toy-domain reference and does not imply parity or correctness for a real legislative pack.

Required CI gates: `foundation` and `workspace` at the exact PR head. The latter runs `pnpm check`, `pnpm audit`, `pnpm build`, and actual Chromium browser tests. Any failed, missing, cancelled or pending check blocks merge.

Source/security review: arbitrary caller-provided facts enter bounded canonical JSON before hashing; replay input is capped at 2 MB, imported checkpoints at 10,000, and malformed or incompatible versions fail closed. Run identity is a content identifier, not proof of publisher authenticity. There are no providers, credentials, migrations or deployed resources. Rollback is a reviewed revert of LM-026 and its tests. No independent human audit is claimed.
