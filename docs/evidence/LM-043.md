# LM-043 – initial fail-closed authorization boundary (INCOMPLETE)

Implements role- and tenant-scoped author authorization with explicit identity-adapter verification, live membership checks, publisher reauthentication age, session expiry, and Origin/CSRF checks for unsafe requests. A no-credentials fixture adapter supports negative testing. Production author preview endpoints use DisabledAuthorIdentityAdapter and always return HTTP 401: no submitted cookie, user ID or claimed role can enable author access. Anonymous public reading remains unaffected.

This PR is a **partial milestone** and must remain draft/unmerged until integration with a maintained external identity provider, trustworthy server session storage and rotation/revocation, role membership backing store, and end-to-end tests through every enabled authoring endpoint are implemented. A TypeScript literal marking serverVerified is NOT proof of authentication when untrusted callers can construct it; adapters must be constructed strictly server-side from validated provider results. Never set tenant scope from request body or headers. There is no real provider, session cookie issuance, source upload, private preview publication or paid provisioning yet.

Unit tests cover denied anonymous requests, wrong-organization access, role permissions, membership revocation, expiry/reauth and CSRF defenses. Browser tests verify the concrete author endpoint denies anonymous and forged headers. This keeps authorization safely disabled while LM-042 schema and provider integration proceed. Rollback: reviewed revert. Independent human audit is not claimed or required as a development gate.

## Follow-on contribution: durable revocation schema (not milestone acceptance)

`db/migrations/0002_up.sql` adds a namespaced, provider-subject-to-internal-actor identity mapping and a database-backed session record. Only SHA-256 hashes of random session and CSRF credentials may be stored; raw cookies, OAuth tokens, client secrets and private documents do not enter these tables. The database rejects invalid/overlong session windows and cross-identity session linkage. Session IDs, cryptographic token digests, issuance/expiry and reauthentication timestamps are immutable after issuance; revocation is permanent for a given record. Role changes and revocations advance `lm_memberships.membership_revision`, and revoked membership cannot silently be restored.

The new tables use FORCE RLS with **no policies** and explicit public privilege revocation, so they remain inaccessible to untrusted application roles. A future narrowly privileged identity service must be configured with correctly scoped policies before these tables can be read or written by live code. This is deliberately a fail-closed *schema/test contribution*, not a working sign-in system.

CI `postgres` now migrates through 0002, runs adversarial author-security SQL, verifies rollback of the disposable migration, and retains the existing tenant-isolation suite. Fixture identities and digests are synthetic. No live provider, sessions, auth cookies, production database or paid resources were provisioned. Migration 0002 has a destructive inverse **only for disposable CI/staging**; production rollback requires snapshot/point-in-time recovery and a reviewed migration plan.
