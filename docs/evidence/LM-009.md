# LM-009 source ingestion: security review and acceptance

## What this PR implements

- Provider-free text and Markdown import, preserving a detached copy of original UTF-8 bytes, SHA-256 of raw bytes, separate extracted text, explicit structural headings/numbering and error diagnostics.
- Provider-free DOCX import over an intentionally restricted ZIP and WordprocessingML subset: stored and DEFLATE entries, exact Word document XML, visible paragraphs, heading styles, list IDs/levels and text from individual table cells/rows.
- The original DOCX ZIP bytes are preserved separately from the extracted reading view; all unsupported processing remains explicit. No current-law inference, execution of document macros, legal filing or network access is attempted.

## Source and security review

The ZIP reader validates the end directory and every local/central entry mapping, file-name bytes, CRC-32, compression flags/methods, zero/oversized offsets, duplicates, traversal, symlinks, per-entry expansion ratio and total size. Limits: 6 MB compressed archive, 8 MB total declared expanded content, 4 MB main XML, 256 entries, 200:1 expansion ratio. Streaming decompression measures actual output against expected limits and checks CRC after extraction. Archives with unsupported ZIP or encryption features fail closed.

The XML reader does not instantiate a DOM, fetch external resources, resolve DTDs, execute macros/relationships, evaluate fields or render HTML. It rejects active object/altChunk constructs, DTD/entity declarations, malformed nesting and non-Word roots. Entity references are decoded only from an allowlist/numeric XML characters. The text/Markdown path uses a fatal UTF-8 decoder; malformed/binary inputs fail instead of silently changing legal source bytes. All imports are local and provider-free.

Limitations remain explicit: displayed DOCX list glyphs/labels may require numbering.xml style resolution, so the import retains the original number ID, hierarchy and a NUMBERING_LABEL_UNRESOLVED diagnostic rather than inventing numbers. Sources with unsupported OOXML/ZIP forms fail closed. This does not guarantee that all possible Word formatting or embedded legal text is recovered; editorial review is required before a source can drive rules.

## Tests, rollback, and operations

Fixtures construct stored and DEFLATE ZIP archives with a heading, nested list clause and a two-row table. Unit tests cover original byte identity, normalized reading output, fidelity between compression variants, path traversal/duplicates, inflated-size bombs, corrupted checksums, macro and active-content rejection, DTDs, missing parts, broken XML, text UTF-8 and CRLF variants. Run `pnpm check`, `pnpm audit`, `pnpm build`, and `pnpm test:browser` at the PR's exact head; only live GitHub check results determine acceptance.

No database or cloud migrations, secrets or paid resources. Rollback: revert LM-009 code and tests through a checked PR. The human-authored source and release model are future work, not certified legal interpretations. Independent human audit is not claimed or a gate.
