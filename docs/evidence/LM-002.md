# LM-002 workspace evidence

Adds a pinned pnpm workspace, strict TypeScript, Next.js application shell, seven domain package boundaries and an explicit fixture-only job entry point. No provider key, database or paid resource is required.

Local verification: `pnpm install --frozen-lockfile`, `pnpm check`, `pnpm build` and `pnpm audit --audit-level=high` pass. Checks include 35 existing foundation tests, four workspace tests, negative client/database and simulation/UI import fixtures, lint, types and a baseline secret-pattern scan. The dependency audit reports no known vulnerabilities at this observation. The baseline secret scanner is deliberately described as limited, not exhaustive certification.

Browser acceptance covers the home page, health endpoint and an axe accessibility scan. It passes locally using Chromium 153 supplied by the @sparticuz/chromium 153.0.0 package and the executable override. The default browser download returned HTML instead of an archive in the development environment; the alternate real browser executes the same test. GitHub workflow run 38945277446 also passed dependency installation/audit, all checks, production build and the standard Playwright browser installation/test on head 6278b5778b60f165996ce777e71b8d224dab0a5e. Subsequent heads must pass their own current checks before merge.

The first script runner used a local IPC socket unavailable in this environment; invoking the same TypeScript scripts through Node's tsx loader removes that unnecessary socket without weakening checks. Negative boundary fixtures also cover a directive after comments, re-exports and dynamic imports.

CI requires foundation and workspace checks, including a production build and actual browser test. Keep these checks current when adding behavior. Rollback: revert the workspace commit; there are no persisted data migrations or provisioned services.
