# LM-012: canonical provision tree and version persistence

Source normalization covers the four imported format families (text/Markdown, DOCX, USLM/House Bill XML, and PDF). It converts explicit headings, provision structure, parentage, displayed labels, source offsets/lines/pages and declared original SHA-256 into version-local, deterministic provision IDs. PDFs and uncertain Word numbering remain visibly unverified/unresolved. Tentative definitions and cross-reference matches are separately labeled as candidates and are never promoted to validated law by this milestone.

The canonical persistence representation is JSON with retained schema fields, validated records and immutable version ID slots. Raw/private source bytes are kept separate, never exported in public explorer data. Publishing an explorer representation requires explicit authorization and rejects unresolved structural errors such as duplicate sibling citations, invalid IDs, missing ancestors or parent cycles. The same version cannot silently overwrite prior text; a new bill version gets a new identity.

Negative tests cover malformed storage, cross-version records, oversized spans/text, parent cycles, duplicate section numbers, unknown PDF content and attempted unauthorized publication. Round-trip tests prove deterministic serialization and preservation of prior versions after renumbering. No actual official source is declared authoritative, no stored document is a compiled rule, and no source interpretation or public release is automatic.

Source/security review: strictly bounded types on the persistence boundary, no remote network/process/provider activity, no evaluation of user text, no React/Next/database imports, explicit publication gates and no private raw bytes in release payload. Rollback: checked revert; no migrations, persisted production records or cloud provisioning. Required checks are current-head GitHub foundation/workspace, including unit, type, lint, dependency audit, production build and browser acceptance. This is AI-authored testing, not a third-party audit.
