# LM-020 immutable compiler and provenance graph

A version-scoped, provider-free rule compiler validates the complete LM-019 JSON envelope and compiles typed conditions, modal force, triggers, exception predicates, actor-targeted effect declarations and public explanation keys to **immutable plain JSON data**. It does not run effects, route government documents or infer actual law.

**Source-to-effect provenance.** Compilation requires a pinned source version and source-byte digest. Every cited provision must exist in the authorized source inventory, and its quote must appear literally. Rule references with stale versions, digests or quotes fail without compiling an executable model. Provenance indexing maps each provision to the exact rules that depend on it.

**Safety and determinism.** Explicit registered actors, external event kinds and supported capabilities are mandatory; unreachable triggers and nonexistent actors are diagnostics. Rules sharing one trigger/actor are conservatively rejected unless explicit precedence orders every potentially conflicting pair. A cycle, unknown predecessor, invalid source inventory or ambiguous ordering rejects the entire model; no arbitrary priority or invented legal outcome is selected. Precedence is treated as a declared model choice, **not** legal priority proven by law. The compiler's canonical JSON snapshot is deep-frozen and detached from caller objects, and its rule order is deterministic. Both Node and browser-compatible TypeScript consumers can read the same data-only compiled format.

Tests in `tests/unit/rule-compiler.test.ts` cover successful compilation, deterministic output, immutability, source digest and quote tampering, missing actor and unreachable trigger, ambiguous conflicts, explicit precedence, dependency cycles, invalid inventories and handoff to the independent LM-019 three-valued guard interpreter.

Security constraints: input size, rule/expression counts and source version/ref limits are checked by the parser and compiler. No dynamic code execution, database, provider, networking, React, or server entry point. No actual bill text or legal opinions are invented. Source authenticity and real bill attachment remain separate release/publishing gates. Rollback by a tested revert; simulations must remain disabled until LM-021 and later milestones.

CI acceptance on the final PR head requires completed `foundation` and `workspace` GitHub Actions including `pnpm check`, audit, production build and Chromium tests. AI source/security review is not independent external auditing.
