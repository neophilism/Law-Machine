# LM-004 integrity work — source-bound evidence

Implementation: public package canonical JSON serializer with explicit allowed types, bounded recursion/node and string counts, SHA-256 for original bytes and canonical UTF-8 objects, content-addressed safe asset names, and complete in-memory release verification against a separate trusted manifest digest.

Source/security review: all volatile metadata participates in content identity; a timestamp update deliberately changes a digest. No implicit authority is inferred from a SHA-256 checksum. Verification includes raw original source bytes and all assets; a separately supplied expected manifest digest is mandatory. Assets use validated, traversal-resistant paths. Missing, extra, duplicate or changed bytes produce actionable non-secret diagnostic codes; no external resources, storage, private source texts or key material are used. Public publisher authentication remains later work.

Automated tests: unit golden vector, key reorder, changed original bytes, asset corruption/mismatch/missing/extras, invalid extension and source, canonical cycles/non-JSON values; browser parity test compiles and evaluates the same source module in Chromium and compares its digest with Node. Acceptance requires both exact-head \`foundation\` and \`workspace\` jobs, including \`pnpm check\`, \`pnpm audit\`, \`pnpm build\`, and real Chromium browser tests. No current-head success or merge is claimed before CI completes.

Data migration: none. Feature-disable/rollback: revert the LM-004 changes via checked PR; earlier LM-003 contract types/validator continue independently. Independent human security review has not been performed and is not represented as certification.
