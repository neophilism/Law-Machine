# LM-042 editorial persistence – source/security review and acceptance

Scope: Postgres schema migration with tenant-isolated organizations, memberships, documents, immutable revisions, source metadata, release metadata, minimal audit events and durable-job records. Composite foreign keys and forced RLS reduce cross-tenant exposure. SECURTY INVOKER (not SECURITY DEFINER) database functions enforce current tenant, current actor, authorized membership, and stale revision expected-value updates. Audit and revision metadata are updated atomically by database transactions.

Security observations and limits: using a PostgreSQL session variable is safe only when set by trusted authenticated server code. LM-043 must verify the user and organization, revoke access on membership change, and deny untrusted direct SQL. The TypeScript server adapter accepts AuthenticatedEditorialScope only after separate authentication; its compile-time marker is not an authentication service. No public author route, private source bytes or API keys are introduced. Each transaction sets the scope using parameterized set_config and cleans up on failure. Raw legal source bytes remain private pending LM-044. Published-release verification remains separate.

Acceptance tests: real disposable Postgres service verifies nonowner RLS, cross-organization write rejection, optimistic stale revision errors, audit/revision rollback after simulated audit failure, transactionally reversible down migration with representative records, and clean down in an ephemeral database. Offline tests check tenant fixture isolation, revision/audit invariants, malformed JSON and transaction rollback behavior. Exact-head foundation, workspace and postgres GitHub jobs are mandatory before merge, including pnpm audit, unit, browser and build checks. Test results must be updated after the final head runs.

No production migration or resource provisioning. Rollback in development: reviewed revert plus ephemeral down script. Production rollback: backed-up database/PITR only (down script is destructive). No independent human audit or certification is claimed.
