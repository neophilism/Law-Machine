# LM-027 – Pinned before/after comparison engine

This milestone adds a provider-free comparison orchestrator that calls an authored scenario executor for two pinned source versions. Both executions receive separately cloned, deeply frozen facts and operational implementation settings. The only default difference is the selected legal framework. Baseline date, jurisdiction, agency, engine and calendar versions must match. Draft and introduced proposals require an explicit hypothetical-enactment assumption, which stays visible in the result.

Semantic checkpoints have authored stable keys. The comparison reports added and removed steps rather than matching unrelated events by sequence number. Differences in legal force, duty state, timing, operational workload, unresolved interpretation, and provenance have distinct reasons. Unknown outcomes remain unknown. Independent named randomness is derived from one shared comparison-input digest, so additional consumption in one subsystem does not shift unrelated streams; each framework retains its own complete run identity.

Automated unit tests cover changed/added/removed steps, common randomness, identical inputs, incompatible dates/versions/jurisdictions, unknown branches, malformed trace data, duplicate keys and attempted mutation of frozen scenario facts. No actual legislation or legal conclusion is represented.

Security review: strict bounded checkpoint and input validation, no dynamic rule evaluation, no React, network providers, database, personal data or credentials. Source digests and trusted publisher assertions are responsibilities of verified releases, not this comparison function. A production first-bill executor is pending source acquisition and LM-030. There are no migrations or deployed resources. Rollback: reviewed revert of this PR. Required exact-head tests: foundation, workspace, pnpm audit/build, and real browser tests. AI source review is not an independent human audit.
